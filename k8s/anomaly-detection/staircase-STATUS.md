## Что сделано

1. Имитация утечки памяти "лестницей" из 5 шагов `StressChaos` (40→200 MiB), жёстко закреплённых за одним подом (`selector.pods`) — график получился чистым, без разрывов между шагами разных подов.
2. `predict_linear(container_memory_working_set_bytes[2m], 60)` — нативный PromQL, без единой строчки Python — поймал будущее превышение лимита за **~40 секунд** до фактического пика нагрузки, при реальном значении метрики 74% от лимита.
3. `Chronos-Bolt` (`amazon/chronos-bolt-small`, предобученная модель с Hugging Face) — поймал угрозу **на 110 секунд раньше** predict_linear(), при значении метрики всего 42% от лимита, используя верхнюю границу доверительного интервала прогноза как консервативный триггер.

## Блокеры по пути (оба преодолены)

1. **`chronos-forecasting` не ставился** — системный Python 3.8.10 (Ubuntu 20.04.6, EOL) слишком старый, `deadsnakes` PPA не публикует пакеты под неподдерживаемую Ubuntu. Решено установкой изолированного **Miniconda** с отдельным Python 3.11 — не трогает ни систему, ни k3s, ни существующие скрипты на Python 3.8. Заняло ~10 минут.
2. **API `chronos-forecasting` отличался от документации в памяти** — `predict_quantiles()` ждёт именованный аргумент `inputs`, не `context`. Поймано и исправлено за один цикл через `inspect.signature()`.
3. **Retention Prometheus (6ч) стёр данные эксперимента**, пока разбирались с Python (детектив с deadsnakes занял часы, перевалило за полночь) — обошлось без повторного прогона лестницы: использованы значения метрики, уже выгруженные ранее из Prometheus в рамках расчёта `predict_linear()`.

## Что это значит для диплома/доклада

Получилось живое, честное сравнение трёх методов на одном и том же реальном сигнале:
- **Реактивная проба** (readinessProbe) — не заметила бы вообще ничего, память ни разу не превысила лимит.
- **`predict_linear()`** — простой, нативный, "бесплатный" (уже встроен в Prometheus) — дал 40 секунд форы.
- **Chronos-Bolt** — предобученная ML-модель, требует чуть больше интеграционных усилий, но даёт **на 110 секунд больше форы**, потому что явно моделирует неопределённость (не только "что вероятнее всего", но и "что может пойти не так").

Это ровно та типология для диплома, которую обсуждали: "нативный DevOps-инструмент vs готовая ML-модель" — с конкретными цифрами по обе стороны, а не только словами.
