# STATUS — эксперимент "лестница" (predict_linear vs Chronos-Bolt)

- [x] Все 5 шагов лестницы прогнаны с зафиксированными таймстемпами (`staircase-log.md`)
- [x] В Prometheus есть непрерывный ряд метрик, покрывающий все фазы (baseline → лестница → восстановление)
- [x] `predict_linear()` — момент срабатывания зафиксирован (`comparison-table.md`)
- [ ] Chronos-Bolt — **заблокировано** (несовместимость Python 3.8 / EOL Ubuntu 20.04, см. `comparison-table.md`)
- [x] Список блокеров с точным текстом — там же

## Что сделано

1. Имитация утечки памяти "лестницей" из 5 шагов `StressChaos` (40→200 MiB), жёстко закреплённых за одним подом (`selector.pods`) — график получился чистым, без разрывов между шагами разных подов.
2. `predict_linear(container_memory_working_set_bytes[2m], 60)` — нативный PromQL, без единой строчки Python — поймал будущее превышение лимита за **~40 секунд** до фактического пика нагрузки, когда реальное значение метрики было ещё на 74% от лимита.
3. Попытка подключить Chronos-Bolt (предобученная ML-модель с Hugging Face) — уткнулась в устаревшую версию Python на сервере, сама PPA-репозиторий для установки новее Python отказала (deadsnakes не собирает пакеты под уже неподдерживаемую Ubuntu 20.04).

## Блокер (подробности — в comparison-table.md)

Коротко: `chronos-forecasting` требует Python новее 3.8, на сервере — только 3.8.10, а попытка поставить 3.11 через `deadsnakes` PPA провалилась, потому что PPA больше не публикует пакеты под Ubuntu 20.04 (EOL). Компиляция Python из исходников как обходной путь признана несоразмерной по времени этой конкретной задаче — не делал, зафиксировал честно.

## Что это значит для диплома/доклада

Даже без Chronos-Bolt результат состоялся: **есть рабочее сравнение "нативный DevOps-инструмент vs факт"**, с конкретной цифрой lead time (40 секунд). Отсутствие ML-модели в этом раунде — не провал, а реальная инженерная проблема (совместимость окружения) с точной диагностикой, что тоже валидный материал для диплома: "готовые ML-инструменты завязаны на современный стек, что создаёт трение при интеграции в legacy-инфраструктуру — ещё один довод в пользу нативных, встроенных решений там, где они достаточно хороши".

Если Chronos всё же нужен для полноты сравнения — варианты на будущее: (а) обновить ОС сервера до Ubuntu 22.04/24.04 (расходится с текущим стендом), (б) собрать Python 3.11 из исходников (~15-20 минут компиляции на этом железе), (в) прогнать Chronos не на сервере, а локально на своей машине по выгруженному CSV — не требует менять прод-окружение стенда. Вариант (в) — самый безопасный и быстрый, если решим вернуться к этому.
