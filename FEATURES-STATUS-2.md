## Как проверить всё локально

### 0. Предпосылки
- Docker Desktop запущен.
- `npm install` в корне и в `backend/` (если ещё не делали).

### 1. Обычный локальный стенд (визуально посмотреть блоки 1-4 руками)

```bash
docker compose up -d postgres backend
npm start
```

Бэкенд поднимется на 4000 (обычная dev-база), фронт — на 3000. Дальше руками:
- Тема/адаптив/календарь — DevTools → responsive mode, 375px и 768px, переключить тему кнопкой в сайдбаре.
- Вложения — открыть любую транзакцию (`/transactions/:id`) или открыть её на редактирование из списка — внизу блок "Чеки и квитанции", перетащить/выбрать файл.

### 2. Backend-тесты (Jest + Supertest)

```bash
docker compose -f docker-compose.test.yml up -d
cd backend
npm install   # если не делали
npm test
```
Поднимает отдельный одноразовый Postgres на порту 5433 (`docker-compose.test.yml`, tmpfs — данные не остаются после остановки), миграции накатываются автоматически перед тестами.

### 3. E2E/визуальные/a11y-тесты (Playwright)

```bash
docker compose -f docker-compose.test.yml up -d   # если ещё не поднят с шага 2 — использует ту же тестовую БД
npx playwright install chromium   # один раз
npx playwright test
```
Сам поднимет отдельный backend (порт 4001, та же тестовая БД) и фронтенд (`npm start`, порт 3000) — **если у вас уже запущен свой dev-сервер на 3000 (например, из шага 1), сначала остановите его**, иначе Playwright переиспользует чужой сервер, настроенный на прод/dev-БД, а не на тестовую.

Отчёт: `npx playwright show-report` после прогона.

Только конкретный слой:
```bash
npx playwright test --project=Desktop     # только десктоп-вьюпорт
npx playwright test e2e/visual.spec.js    # только визуальные скриншоты
```

### 4. Всё сразу

Порядок значения не имеет — можно гонять `npm test` (backend) и `npx playwright test` независимо, оба используют одну и ту же тестовую БД на 5433, если она поднята.

## Компромиссы и незакрытые мелочи

- **Визуальные скриншоты (`e2e/visual.spec.js`) исключены из CI-гейта.** Baseline-картинки сгенерированы на Windows; на Linux-раннере GitHub Actions даже нетронутая вёрстка рендерится с другим антиалиасингом шрифтов и не пройдёт побайтовое сравнение — это дало бы постоянные лже-провалы, а не сигнал о реальных регрессиях. Локально (`npx playwright test`) этот слой прогоняется и работает, в CI — сознательно пропущен через `--grep-invert "visual regression"`. Если нужен визуальный гейт именно в CI — надо либо перегенерировать baseline прямо на Linux-раннере (первый прогон CI сам создаст `-linux.png` файлы, которые можно скачать из артефактов и закоммитить), либо гонять Playwright в Docker-образе с фиксированным окружением рендеринга.
- **Вложения недоступны в момент создания транзакции** (только после сохранения, в режиме редактирования/на странице деталей) — у ещё не существующей транзакции нет `id`, к которому привязать файл. Не стал городить двухфазное создание (сохранить черновик → сразу открыть на редактирование) ради этого.
- Один тест (`limits.spec.js` на Desktop) один раз словил таймаут при прогоне **всего** сьюта подряд (~4+ минуты), но стабильно проходит в изоляции — похоже на ресурсный затор от долгого прогона, а не реальный баг; в CI на этот случай уже включены `retries: 1`.
- Не трогал существующие 4 ESLint-warning'а фронта (missing hook deps, unused vars) — не относятся к этому ТЗ; CI-шаг сборки фронта намеренно собирает с `CI=false`, как и прод-Dockerfile, чтобы не блокировать деплой из-за них задним числом.
